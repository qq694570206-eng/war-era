# 战争纪元：按验收推进的开发路线 v2

- 日期：2026-11-10；状态：优化提案，待评审。
- 依据：[玩法优化](optimization-design-v3.md)、[技术方案](tech-architecture-v3.md)。
- 当前只有静态源码检查；任何“存在脚本”均不等于“模块完成”。不承诺未经编译和测量的工期。

## 1. 里程碑

| 阶段 | 工作边界 | 必须提供的验收证据 |
|---|---|---|
| M0 可重复工程 | 固定 Editor/依赖；提交 meta/场景/配置；解除程序集环与私有字段访问错误；显式启动顺序 | 干净检出可打开且编译零错误；菜单进入 Battle 再退出；Android 开发包构建成功及日志 |
| M1 经济闭环 | 双方开局 HQ/矿场/采矿车；资金、电力、施工、队列、退款；单一实体生命周期 | 玩家采集→建兵营→出兵；双方采矿入账互不串账；取消不重复退款；缺电可恢复；死亡索引无残留 |
| M2 战斗闭环 | 固定 tick、命令校验、A*、空间查询、迷雾、伤害及 AI | 三条路线绕障；两队不同目标互不干扰；不可达不穿墙；AI 无免费出兵；隐藏单位不可索敌；双 HQ 同 tick 死亡为平局 |
| M3 可用体验 | 移动端手势、确认建造、简短教学、暂停、小地图基础显示 | 5 人试测记录；至少 4 人无需口头帮助完成教学；UI 不穿透；双指不误发移动；暂停无生产/伤害推进 |
| M4 恢复与稳定 | 强类型快照、备份恢复、后台行为、实机压力与长测 | 存读档字段与继续运行结果一致；坏档能回退；强杀后可读最近完整档；完整压力报告达到约定预算 |
| M5 体验扩展 | 第二地图、阵营倾向、T2、编队与雷达扫描 | 通过下述扩展门槛后单独细化，不能反向阻塞切片 |

M0 → M1 → M2 → M3 → M4 为依赖顺序；每阶段通过后才进入下一阶段。编译基线未建立前不继续添加广告、内购、排行榜或新主题脚本。

## 2. 验证矩阵

| 层级 | 核心场景 | 通过标准 |
|---|---|---|
| 内容校验 | 缺失定义/重复 ID/无效前置/越界出生点/断路/缺图 | 阻止构建或进入战场，指出资产路径与字段 |
| 规则测试 | 扣费退款、缺电、队列出口阻塞、重复命令 | 资金不为负，不重复结算，失败原因明确 |
| 战斗测试 | 等成本克制、同 tick 互杀、目标死亡/失去视野、延迟 AOE | 顺序稳定，伤害只结算一次，隐藏实体不泄露 |
| 导航测试 | 两队异目标、墙角、堵路、建筑撤销、不同实体半径 | 无穿墙；路径失效后重算；失效缓存不继续使用 |
| 快照测试 | 排队生产/携矿/延迟伤害/AI 进攻时存读档 | ID 与引用恢复正确；经济和冷却不重复；固定版本继续 200 tick 对比状态摘要 |
| 异常恢复 | 临时文件截断/正式档损坏/缺内容/未知版本 | 不覆盖原档，备份有效则恢复，无效则安全回菜单 |
| 实机集成 | 进入退出 10 次、暂停恢复 20 次、30 分钟混战 | 无崩溃、无逻辑失步、无持续资源增长；附 profiler 与机型记录 |

状态摘要按稳定实体 ID 排序，包含资金、HP、命令、队列、随机状态与 tick；浮点比较采用在固定版本内明确的容差，不以画面相似作为恢复成功依据。

## 3. 扩展门槛

只有 M4 通过后才启动 M5。第二时代开始前还需：二战形成稳定完整对局；第二地图验证路径与扩张规则；所有主题数据能独立校验；关键规则已脱离表现层。

远程内容包须先有本地双主题加载与释放证据。商业化须先有完整购买状态机与正式平台接入验证；当前模拟购买、广告奖励不计作完成。联网须另立同步模型与跨平台验证方案，不沿用“命令模式即支持锁步”的假设。

## 4. 交付记录规则

每个阶段记录提交版本、验证日期、环境、通过项和未通过项。功能状态仅使用“设计 / 源码存在 / 已编译 / 可玩 / 实机验收”五档，禁止用一列完成勾选混淆不同成熟度。

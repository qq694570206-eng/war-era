## 决策 1：2D 精灵图 — 实现方案

### 渲染架构
- **SpriteRenderer** + 正交摄像机（2D 模式）
- 每个单位一张精灵图（或多帧 Sprite Sheet）
- 朝向处理：8 方向精灵切换 或 单图 Canvas 旋转（阶段 D 定）
- 建筑用等距视角精灵图（已有 12 张 AI 生成的占位图）

### 精灵图规格
| 类型 | 尺寸 | 帧数 | 方向数 |
|---|---|---|---|
| 步兵 | 128×128 | 4 帧/动作 × 4 动作 | 8 方向 |
| 载具 | 192×192 | 2 帧/动作 × 3 动作 | 8 方向 |
| 建筑 | 256×256 | 1 帧（+建造进度帧） | 1（等距固定） |
| 特效 | 128×128 | 4-8 帧 | — |

### 动作清单
| 动作 | 步兵 | 载具 |
|---|---|---|
| Idle | 4 帧 | 2 帧 |
| Move | 4 帧 | 2 帧 |
| Attack | 4 帧 | 2 帧 |
| Death | 4 帧 | 2 帧 |

## 决策 3：AI 生成 — 多帧一致性策略

### 核心挑战
AI 生成的多帧精灵图之间存在一致性差异（同一单位在不同帧看起来不一样）。

### 解决方案
1. **生成单张高清图 + Canvas 程序化动画**
   - 生成一张 1024×1024 的单位主图
   - 用 Canvas/Unity 变换模拟动画（旋转/偏移/裁剪）
   - 优点：一致性 100% 保证
   - 缺点：动画感不如真正的帧动画

2. **生成 Sprite Sheet（多帧拼图）**
   - Prompt 明确要求 "sprite sheet, 4 frames, same character, consistent design"
   - 生成后手动裁剪成单帧
   - 优点：真正的帧动画
   - 缺点：帧间一致性不可控，可能需要多次生成

3. **混合方案（推荐）**
   - 单位主体用单张高清图 + 程序化动画（旋转/后坐/弹跳）
   - 独立部件（炮塔/枪管/履带）单独生成或程序化绘制
   - 特效（爆炸/枪口闪光）用 AI 生成多帧
   - 平衡一致性和动画感

### 生成优先级
| 优先级 | 资产 | 数量 |
|---|---|---|
| P0 | 二战背景全部单位（14 种 × 1 张主图） | 14 张 |
| P0 | 二战背景全部建筑（8 种 × 1 张） | 8 张 |
| P1 | 地形 Tileset（草地/城市/道路） | 3-5 张 |
| P1 | 特效（爆炸/枪口闪光/核弹） | 5-8 张 |
| P2 | 其他 4 个背景包的单位/建筑 | 每包约 22 张 |

## 决策 4：免费+内购+广告 — 变现设计

### 变现原则
**绝对不卖数值**——内购不提供战斗力优势，只提供便利性和外观。
**广告不打断战斗**——战斗中不弹广告，只在非战斗场景展示。

### 内购项设计

| 分类 | 内购项 | 价格 | 说明 |
|---|---|---|---|
| **背景包解锁** | 冷兵器背景包 | ¥6 | 解锁冷兵器阵营+兵种+地图+战役 |
| | 一战背景包 | ¥6 | 同上 |
| | 二战后局部战争 | ¥6 | 同上 |
| | 现代战争背景包 | ¥12 | 最复杂背景，定价略高 |
| | 全背景礼包 | ¥30 | 解锁全部 4 个额外背景（对比单买 ¥30 省 ¥6） |
| **便利性** | 建造队列扩展 | ¥6 | 生产队列从 5 扩到 8 |
| | 编队槽位扩展 | ¥6 | 编队从 5 组扩到 8 组 |
| | 存档槽位 | ¥3 | 遭遇战存档从 1 个扩到 5 个 |
| **外观** | 阵营皮肤包 | ¥6/包 | 改变单位配色/旗帜（不改数值） |
| | 特殊击杀特效 | ¥3 | 替换爆炸/死亡特效外观 |
| **战役** | 完整战役 DLC | ¥12/背景 | 每背景 15 关完整战役（免费版只有 3 关体验） |

### 免费内容（不花钱能玩的）
- 二战背景完整遭遇战（全部单位/建筑/地图）
- 战役前 3 关
- 2 个阵营（盟军/轴心）
- 3 张地图
- 3 档 AI 难度

### 付费墙位置
```
免费玩家：二战背景遭遇战 + 3 关战役 → 完整可玩，无数值限制
付费玩家：额外背景包 + 便利性 + 外观 + 完整战役
```

### 内购技术实现
- 用 **Unity IAP**（In-App Purchase）插件
- iOS: StoreKit
- Android: Google Play Billing
- 非消耗品（背景包解锁）+ 消耗品（无）+ 订阅（无）

### 广告设计

**广告原则**：战斗中零广告，只在非战斗场景展示，可跳过，不强迫。

| 广告位 | 类型 | 触发时机 | 奖励 | 频率限制 |
|---|---|---|---|---|
| **激励广告-资源** | Rewarded Video | 战斗中点击"看广告+500矿石" | +500 矿石 | 每局 1 次 |
| **激励广告-秒建** | Rewarded Video | 建造中点击"看广告立即完成" | 当前建筑秒完成 | 每局 3 次 |
| **激励广告-复活** | Rewarded Video | 基地被摧毁后"看广告恢复 HQ 50%HP" | HQ 恢复 | 每局 1 次 |
| **插屏广告** | Interstitial | 遭遇战结束（胜利或失败）后 | 无 | 每 3 局 1 次 |
| **横幅广告** | Banner | 主菜单底部 | 无 | 常驻（付费去广告可关闭） |

**去广告内购**：

| 内购项 | 价格 | 说明 |
|---|---|---|
| 去广告 | ¥12 | 永久移除所有广告（激励广告转为直接领取奖励） |

**广告技术实现**：
- **Unity Ads**（官方，零额外 SDK）
- 或 **AdMob**（Google，填充率高）
- 建议：Unity Ads 为主（集成简单），AdMob 备选

**广告在代码中的接入点**：

| 模块 | 接入方式 |
|---|---|
| 激励广告-资源 | EconomySystem 新增 `WatchAdForOre()` 方法 |
| 激励广告-秒建 | BuildSystem 新增 `WatchAdToFinishBuild()` |
| 激励广告-复活 | GameManager 在基地被摧毁时弹出选项 |
| 插屏广告 | UIManager 在 ShowGameOver 后延迟 1 秒展示 |
| 横幅广告 | UIManager 在主菜单挂载 Banner |
| 去广告 | AdsManager 检查 IAP 状态，已购则跳过所有广告 |

### 新增脚本
| 脚本 | 职责 |
|---|---|
| IAPManager.cs | 内购购买/恢复/验证 |
| AdsManager.cs | 广告加载/展示/频率控制/去广告检查 |

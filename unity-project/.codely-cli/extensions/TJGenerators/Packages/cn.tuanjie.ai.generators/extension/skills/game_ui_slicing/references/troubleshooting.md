# 失败时按现象处理

| 现象 | 先查 | 应采取的动作 |
|---|---|---|
| 请求已提交但长时间无图 | task_id、poll 错误、check_task 实际状态 | 继续同一任务，不能重交生成 |
| UI kit 第二步参数被拒 | 当前 schema、有效 provider、prompt | 补齐原 prompt/真实截图 URL，沿用返回 provider；不传全能日辉单图 provider |
| file_upload 成功但生成拿不到图 | already_uploaded、PUT 的 HTTP 状态 | 实际 PUT 字节；用 file_url 而非 upload_url |
| 改图后工具仍看到旧版本 | 上传路径和内容 SHA256 | stage-upload 生成新哈希文件名再上传，不重复用旧路径 |
| 原图 .png 看起来有棋盘格 | alpha 统计、格子是否实际像素 | alpha 全不透明说明可能烘焙棋盘（常因 prompt 口头要透明）；改用 `is_segmentation=true` 且 prompt 不写透明，或键色底重试；不能两种灰都删掉冒充抠图 |
| foreground touches crop boundary | 原图是否已断边、矩形是否太小 | 可恢复则扩大实测矩形；原件已经截断则补原图/单件生成，不靠 padding 掩盖 |
| no visible foreground | 坐标、键色、主体是否同色 | 先改坐标/输入，别增加 tolerance；同色改用 alpha 或手工遮罩 |
| 图标孔洞仍有底色 | scope=edge 的封闭区域 | 确认孔洞确实是背景后使用 all；主体也同色时不能用 all |
| 羽毛/叶片分叉仍有亮紫斑，但外轮廓已干净 | 狭缝被黑描边隔断，未被 edge 连通域触达 | 核实空隙属于背景；按命令参考试 all + 实测混色范围，复查同色主体。边缘计数下降不代表这些口袋已修复 |
| 洋红/绿色晕边 | 原生 alpha 还是色键；边缘混色 | 原生层优先；调小范围做一件对比。大面积染色/玻璃不要用模糊或全图去色 |
| 小预览过关，1:1 图上有细粉边 | 联系表缩略隐藏了 AA 污染 | 看深浅底 1:1；硬边美术可显式试 edge_unmix=2 并比较，不能只看 alpha 数字 |
| 九宫格目标小于固定边缘总和 | 源图像素与目标显示像素的倍率 | 按实际像素比例填写 preview_scale，再测目标尺寸，不削小源 border |
| 键色被报告为“主体内部误删” | 检测只用了外接矩形，还是实际轮廓 | 圆角/斜切角外的背景本来就在外接矩形内；先看输出，别反复模拟误判 |
| normal/pressed 切换时跳动 | trim、画布、主体位置、pivot | 同画布不紧裁，保留一致坐标；尺寸相同仍要检查主体视觉位置 |
| 九宫格角花拉长 | border 是否切过装饰、源中心是否可拉伸 | 重新测最终图；复杂横跨纹章改成背景+独立装饰层 |
| 字体压边但“没溢出” | content_rect 与真实字形，而非 TMP 容器 | 查最长文本/fallback/基线，调整文本安全区或布局；不默认缩小所有字 |
| 按钮空白也能点/装饰挡点击 | 透明边距与引擎 raycast/hit area | 明确设置逻辑点击区；视觉 alpha 不必然等于点击范围 |
| 图集黑边/漏色 | straight alpha、过滤、压缩、padding/extrusion | 检查导入和合图设置；间隔不是挤边像素，先用无压缩预览对比 |
| Pro/Qwen 返回层少于资产清单 | 实际层内容、metadata | 按收到的层登记，缺项单独补；不把 base image 算作独立按钮 |
| metadata 框与图层尺寸对不上 | 原点、单位、原画布/局部层区别 | 保留原 metadata，先确认坐标语义；别直接重复裁 bounding_box |

失败后记录“哪个文件/阶段、当前参数、看到的现象、修改了什么”。同一问题两轮无改善换处理方法或索取必要输入，不继续盲调参数。只有用户已授权的生成范围内才补生成，不静默换 provider。

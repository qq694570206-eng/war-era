# 可直接填写的生图提示词

先把花括号替换成任务的实际要求。这些是图像内容说明，不是 API 参数。先查看当前工具支持的像素尺寸、参考图、模型与结果结构；不杜撰参数名或层提取能力。不同工具若用独立 negative prompt 字段，可把“避免”项移入该字段。

## 背景 / 透明（硬规则）

- **默认走智能抠图**：MCP/工具传 `is_segmentation=true` + `output_format=png`（与编辑器「自动抠图」同一能力）。**不要**在 prompt 写「透明背景 / fully transparent / alpha / checkerboard」——模型常把预览棋盘格烤进 RGB，inspect 会显示全不透明。
- Prompt **只描述主体与布局**；需要键色兜底时才写「全画布均匀纯色 #RRGGBB」，并同时设 `is_segmentation=false`。
- 下载后必须 inspect：有真实 alpha → `background.mode=alpha`；仍不透明或烘焙棋盘 → 键色重试一次，禁止继续口头要透明。
- 纯色键避开主体颜色：紫红魔法不选洋红底，绿色植物不选绿底。软阴影/玻璃优先真 alpha；色键无法恢复真实半透明。

## 从实际游戏工序提炼的主线

1. 先用一张概念图或已接受的参考确定材质、配色、光照，再让背景、面板、按钮、图标共用这一风格。参考用于保持风格，不把概念图当作可直接切出的全部素材。
2. **整屏背景和可复用控件分开出图**：标题/战斗/结算背景按目标屏幕比例生成；控件用智能抠图（或键色兜底）单独出图。不要把按钮、中文标题、数值永久画进背景。
3. 图册按用途排：底板/槽位、横向按钮/名牌、圆形技能图标、独立资源小图标。每批只放便于清点的数量，留足装饰安全边距，不把源工程的具体行列数当通用标准。
4. 提示词重点写正视、完整外轮廓、无文字、不重叠和可拉伸中部。全能日辉：`provider="frontier_sunburst"` + `output_format="png"` + **`is_segmentation=true`**；实际结果仍要解码检查 alpha。
5. 生成后实测各个部件，再裁切、（仅键色图）去底色、检查边缘。源图写了“洋红”仍可能存在颜色漂移，不能只认 #FF00FF；正文由引擎渲染，按部件内框给安全区。
6. 普通按钮的按下/禁用反馈通常可由同一底板配引擎 tint/亮度/交互状态实现，不必为了三个状态重新生成三张几何容易漂移的图。用户明确要三张 PNG 时可从同一正常态派生简单视觉状态并保留 alpha；若需要不同结构/图案再生成艺术状态图。
7. 图标等比显示，面板按需要九宫格；最后在真实设计尺寸和最小窗口下验收文字与点击。源工程中的数值和布局只说明方法，不复制到新游戏。

这里的模板是对已用工序的通用整理，不声称是某次生成调用的原始逐字提示词。

## A. 全批共用的风格说明

选用全能日辉时，先在任务指令中明确“使用全能日辉”，再调用 `generate_image`，例如：

```json
{"provider":"frontier_sunburst","output_format":"png","is_segmentation":true,"image_size":"square_hd","resolution":"2K","prompt":"下方已经填写好的美术提示词（勿写透明背景）"}
```

这是选定模型后的调用示例，尺寸/分辨率按实际素材预算调整；竖屏背景替换为对应的 image_size，不把方图示例照抄到所有素材。美术 prompt 本身描述图像内容，provider / `is_segmentation` 才决定模型与抠图。

```text
制作可投入游戏使用的二维 UI 美术素材。
主题：{例如温暖手绘炼金工坊}。
视觉语言：{材质、线条粗细、边框形状、圆角、装饰密度}。
配色：主色 {色值}，辅助色 {色值}，强调色 {色值}。
光照：{例如左上柔光}，所有部件光照方向和描边宽度一致。
参考图用于统一材质、色彩和造型；不把参考图的文字、布局或复杂背景烘焙进部件。
正面平视、无透视倾斜、轮廓清晰，适合 {目标显示尺寸} 阅读。
```

同一批次复用这段。不要每张随机换画风词。先出 1 个有代表性的按钮或面板，确认后作为后续参考；这是检查顺序，不强制每次都向用户多问一次。

## B. 独立部件（默认优先）

```text
{粘贴风格说明}
只画 1 个 {文件名/部件描述}，用于 {用途}。
输出画布 {宽×高像素}；主体 {目标宽高比}，正面居中。
完整保留四角、边框、阴影和装饰，四周至少留 {像素或比例} 空白。
主体内部保留 {文字区域描述} 的低细节留白，之后由游戏引擎放文字。
{若需九宫格：四角装饰固定，四条边中段能直线延展，中央材质平稳，没有横跨整块面板的斜线、人物或完整纹章。}
{默认不写背景透明句；仅键色兜底时：全画布均匀纯色 #RRGGBB，没有渐变、棋盘格、地面或环境。}
不画任何文字、字母、数字、标签、标尺、网格、外部投影场景或界面演示。
不是一张完整游戏截图，只交付该独立部件。
```

## C. 小批图册（适用于轮廓简单的同类资产）

```text
{粘贴风格说明}
制作一张可独立裁切的游戏 UI 部件图册，画布 {宽×高像素}。
只包含以下 {数量} 项，每项只出现一次：
1. {部件及形状}
2. {部件及形状}
3. {部件及形状}
4. {部件及形状}
按 {行×列} 排布，各部件完整位于自己的区域中。
区域之间保留至少 {像素} 间隔；主体、阴影、粒子和角花不得跨区或相互触碰。
不画格线、编号、名称、文字或展示台。不要透视、不要把部件拼成成品界面。
{默认不写透明背景；仅键色兜底时写全画布均匀 #RRGGBB。}
```

默认每张 4–6 个同类部件便于检查，但用户已有大图不因此重做。该提示词只表达布局意图，不能证明实际结果遵守网格。最终必须按实际像素测量；框重叠或跨区就调整分区/重出单件，不直接均分。

## D. 按钮状态（逐张参考同一正常态）

```text
以这张 {正常态参考图} 为准确的形状参考，生成 {pressed/disabled/selected} 状态。
保持相同画布、主体位置、外轮廓、边框厚度和角花大小，不增删部件，不改变整体宽高比。
只改变 {按下：内表面稍暗与轻微内阴影；禁用：降低饱和度与对比；选中：强化边框颜色}。
不添加文字。勿写透明背景；与正常态相同的 `is_segmentation` / 键色策略。
```

不能用“正常态大概差不多”代替状态对齐。输出若漂移，先在固定画布对齐；不要分别紧裁来掩盖问题。状态图尺寸相同是必要条件，主体位置相同还需要看图。

## E. 针对一个失败部件的修订

```text
基于附图只修复 {具体部件}：问题是 {右上角花被截断/边框太厚/文字空白区不足}。
保留 {已正确的颜色、材质、轮廓、画布}。
改动为 {具体可检查要求，例如四周至少 24 像素空白、内框宽度占主体 70%}。
输出独立部件，不含文字；勿写透明背景（抠图用 is_segmentation，或键色兜底写均匀 #RRGGBB）。
```

不要用“更高级、更好看”替代可检查的变化。连续两次不改善时调整素材结构或输入，不能无上限重新生图。记录实际提示词和 provider/任务 ID，不能把本模板当成已执行过的生成记录。

## F. 完整界面效果图（仅用户需要视觉方向时）

作为单张效果图时用于评估布局，标记 `mockup`。用 `generate_image`，需要全能日辉风格时选 `frontier_sunburst`（`is_segmentation=false`）；已有截图需要分层时走 MCP `generate_image_layers`。不要把效果图当成已经交付了切图。完整界面中的相互遮挡、半透明叠加与烘焙文字无法仅通过裁矩形还原为干净控件；缺的部件用 B/C/D 模板全能日辉单独补齐。

整页效果图 /（可选）Kit 共用 prompt 骨架：

```text
{粘贴风格说明}
设计 {横/竖屏，目标比例} 游戏的 {商店/背包/战斗HUD/设置} 界面。
布局：{上、中、下各区域的位置、大小关系与功能}。
需要的可复用部件：{面板、按钮、槽位、图标逐项列出}。
部件轮廓清楚，避免不必要的相互遮挡；装饰不要压住文字预留区。
按钮留空，数值与中文正文不烘焙进美术；文字由游戏引擎实时渲染。
边框与角花完整，面板中部适合拉伸，保持所有部件统一材质和光照。
```

走旧 Kit 时：第二步原样保留并传真实 screenshot 路径/URL 与有效 provider（仅 seedream_pro/frontier）。不要把 B 模板的“只画一个部件”用于整页效果图。

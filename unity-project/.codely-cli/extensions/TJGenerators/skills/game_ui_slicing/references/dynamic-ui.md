# 可变 UI：美术分层，运行时驱动

本流程把图片当作皮肤，变化的数据与行为由运行时组件负责。原工程的标题、姓名、资源数字、生命状态和按钮反馈均与图片分离；新项目继续使用这一原则，不把一张静态成品界面当可交互 UI。

## 先分清哪些东西会变化

| 对象 | 生图/切图交付 | 运行时职责 |
|---|---|---|
| 标题、姓名、描述、价格、倒计时 | 无文字的底板与装饰；固定艺术字仅按用户要求单独一层 | 文本组件、字体、语言、换行/省略策略、刷新数值 |
| 血条、能量条、经验条 | 外框、槽底、独立填充纹理；不能把满条与框烘焙成一张 | 计算比例，裁剪/遮罩填充，框保持原样，数值独立文本 |
| 心形生命 | 单独的心形图标、可选空心图标 | 按生命值增减/替换实例；不生成每一种血量的整排心形图 |
| 技能冷却 | 技能图标、外框、可选遮罩外观 | 径向/线性遮罩、倒计时文字、可用/不可用交互状态 |
| 按钮状态 | 通常只需一张正常态底板；结构变化时单独状态图 | 引擎 tint、按下偏移/缩放、禁用交互；需要三张 PNG 时保留共同 alpha/画布派生 |
| 背包格、列表、商品卡 | 一个可复用槽位/卡片皮肤，物品图另出 | 数据填槽、数量角标、选中框、列表布局与滚动 |

不要把当前金币“100”、姓名或“75%”画进纹理，也不要让生命值变化去拉伸带着完整边框的图片。装饰节点通常不拦点击，实际交互区单独设置。

## 血条的三层结构

顺序是**槽底 → 填充 → 前景外框 → 数值文本**。前景外框的中间窗口必须透明，否则会盖住填充；已有不透明底板也可在引擎中作为底层使用，但不要把它冒充透明前景框。

- 外框可九宫格，按容器尺寸变化；血量变化时外框尺寸/角花不能变化。
- `ratio = clamp(current / maximum, 0, 1)`。maximum≤0 时按项目约定显示空条/不可用，必须避免除零；本技能离线预览采用空条。
- 纯色填充可直接改可见宽度，锚点/pivot 固定在填充起点；有纹理时先按**满值**布置，再用 Filled/裁剪/材质参数减少可见范围，避免把纹路和端帽压缩。不要缩放整张带框图片。
- 明确从左→右、右→左或下→上的填充方向。默认示例从左到右；0% 无填充，100% 恰好覆盖内部区域，不越过框。
- 圆角用内部遮罩裁剪，不能靠拉伸整框补圆角。填充源图不要含大段透明留白，否则低血量时会出现“数值大于零但条没显示”。裁去无用留白或测量填充素材的有效矩形。
- 若要随血量变红/黄/绿，填充使用中性灰白纹理或程序图形，再由运行时着色。强绿色纹理乘红色会变暗，不适合自由染色。
- 更新数值、比例和颜色使用同一份状态。伤害残留条/缓动条可作为另一层，不修改真实数值层的含义。

## 文字与数字

先用**最长实际文案、最大位数、中文标点和本地化字符串**确定容器。文字安全框取部件内框，避开角花；字形的基线、fallback、行高也要验。

把切图拼成页面时必须使用已测量的 content_rect 及其显示坐标映射，不要又手填一套“距左 30px、距顶 20px”的文字/商品占位框。示意虚线框也不能压到角花。每个子卡片使用自己的文字安全区；父面板的文本安全区不等于对子控件图片统一裁剪。若某一文字区需要不同留白，应单独测量并记录该区域，不能临时挪出安全区却仍沿用旧验收结论。

- 姓名/描述按项目选择换行、固定行数、省略号或展开方式。不要偷偷删字；重要数值应完整显示。
- 数字位数变化要预留宽度，必要时使用等宽数字或固定对齐；不要因为 9→10 导致邻近图标来回跳动。
- 数字格式（千分位、K/M、单位、小数位）是产品规则，确定后统一使用，不能为了放得下随意把 999999 换成含义不清的缩写。
- 不默认无限 AutoSize。先改善容器、间距和换行，再在项目允许的最小字号以上调整。
- 数字叠在变色填充上时，各血量阶段都检查对比度；可用描边、阴影或独立文本底，不只在满血绿色上检查白字。
- 文字由引擎渲染。离线拼装时可以叠加测试文字，但这些预览不能重新当作无字游戏素材交付。

## 给 Generator 的血条部件提示词

沿用已确定的全能日辉风格/参考；调用时 `provider=frontier_sunburst`、`output_format=png`、**`is_segmentation=true`**。**不要**在 prompt 写透明背景。

```text
{统一风格说明}
生成可拆开用于运行时血条的三个独立部件，清楚分隔，彼此不重叠：
1. 横向血条外框：{材质、尺寸比例}，四角完整。框的中央窗口为空（镂空），窗口中没有已填满的条、数字或文字。
2. 血条槽底：独立的暗色横向底条，没有外框、文字、数字、端部装饰，形状能放入外框内侧。
3. 血条填充纹理：独立中性灰白横向纹理条，没有边框、数字、彩色标记或空白百分比区域。将由引擎统一着色并按生命值裁剪。
三个部件各自完整，留足空白，正面视角，无透视。
不把血量状态画死，不画“HP”“100”“75%”或任何文字。所有文字稍后由引擎渲染。
```

智能抠图失败（无 alpha / 烘焙棋盘）时再改用键色兜底：`is_segmentation=false`，并在 prompt 加「全画布均匀 {键色}，包括外框中央开口」。外框中间不应留下不透明键色窗口（用 `scope=all` 或真 alpha）。纯平填充若无需美术纹理，可直接使用引擎的纯色图形。

## 离线动态验收脚本

从 [dynamic-ui.template.json](../assets/dynamic-ui.template.json) 复制到任务目录，替换真实路径和**实测**几何。示例矩形不是自动推断结果。

```text
python "SKILL_DIR/scripts/preview_dynamic_ui.py" "WORK/dynamic-ui.json" --out "WORK/dynamic-qa-v1"
```

输入约定：

- 仅文字/数字测试时删除 `bar` 整段或设为 null，只填写 text_samples；不为文字任务强行增加血条。
- 图片路径和 `font_path` 相对于 config 文件目录解析，也支持绝对路径。字体必须真实存在并覆盖测试语言；用项目字体或本机已提供的字体，不把系统字体复制进可分发技能包。
- `bar.size` 为参考显示像素；`frame_border_ltrb` 是**源框 PNG** 的边界，`frame_scale` 与静态九宫格一致。
- `fill_rect`、`text_rect` 是**显示后的 bar 内部坐标**，以左上为原点 `[x,y,w,h]`；不可直接拿 source_rect 填。`fill_radius` 是显示像素内圆角。
- `frame/track/fill` 必须是三个可独立组合的文件。前景框的开口至少要能看到后面的填充；脚本拒绝完全覆盖填充区的不透明前景框。
- `colors` 按 up_to 从小到大，末项为 1；不需要变色就填唯一白色 `[255,255,255]`，保留原填充颜色。
- 血条文字默认 1px 黑描边，防止白字落在黄色填充上失去对比。可用 text_stroke_width（0–4）/text_outline（RGB）调整；文字范围包含描边，不能靠溢出描边增加可读性。
- `states` 使用 `[current,maximum]`。建议至少 0%、1%、25%、50%、99%、100%，以及负值、超过最大值、maximum=0 和大位数；重复相同数学规则无需无穷组合。
- `canvas_scales:[1,0.5]` 表示整体等比缩放，图片、框、字与遮罩一起减半。它和“血条容器变窄而框厚度不变”是不同测试。
- `text_samples` 指定实际字符串、容器、字号和 wrap。脚本会报告溢出，不会静默缩字/截字。自动换行是按字宽的简化预览，实际引擎的排版策略仍须复核。

输出每个数值状态的深浅底 PNG、缩放版、`states-contact.png`、文字样本和 report。正值在参考尺寸至少保留 1 像素填充，0 值严格空；report 记录此量化策略、clamp 后数值、填充宽度、文字范围和源哈希。`text_geometry=failed` 时退出码为 2，但保留失败预览以便定位，换新目录重跑。

离线工具只验图层组合、数值裁剪与文字尺寸；它不是实际游戏运行截图，字体覆盖、观感和引擎实现不能由脚本退出码代替。实际接入时仍检查游戏里的 0/1/满值、最长文案、最大位数、最小窗口、血量刷新和按钮输入。

## 引擎接入提示

Unity/团结 uGUI 常用静态 Image 外框、独立 Image 填充（Filled/Horizontal、fillOrigin 与方向对应）、Text/TMP 数值；fillAmount 用归一化比例，别把整框的 scale.x 设成血量。传统 Text 与 TMP 的字体与溢出 API 不混用。UI Toolkit、Godot、Unreal 用对应的裁剪/进度组件，同样保留分层和安全区契约。

按 [engine-handoff.md](engine-handoff.md) 对真实 UI 系统验收。没有引擎连接时明确“只完成素材和离线动态预览，未验证运行时绑定”，不要补一句“已支持动态血条”冒充已接入。
